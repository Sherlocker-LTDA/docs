Uma **engine** é a configuração de uma análise: para cada bloco de verificação (ex.: `SITUACAO_CADASTRAL_CNPJ`, `SANCAO_NACIONAL`), a engine define a **ação** aplicada quando o bloco é acionado — bloqueio, alerta ou ignorar — e os **parâmetros** de avaliação (ex.: capital social mínimo). Toda análise criada via `POST /v1/analyses` roda com exatamente uma engine, e é ela que determina o `verdict` final.

## Ações e efeito no verdict

| Ação | Efeito no bloco | Efeito no `verdict` |
|------|-----------------|---------------------|
| **Bloqueio** (`block`) | Bloco acionado sai com status `blocked` | Qualquer bloco `blocked` → `reprovado` |
| **Alerta** (`alert`) | Bloco acionado sai com status `alert` | Um ou mais blocos `alert` (sem nenhum `blocked`) → `alerta` |
| **Ignorar** (`ignore`) | Bloco não é avaliado | Nenhum |

Se nenhum bloco sai em `alert` ou `blocked`, o `verdict` é `aprovado`. Se o motor termina mas um ou mais blocos ficam `unavailable` (a fonte de dados falhou), o `verdict` é `incompleto` — confira o campo `coverage` da resposta. Veja [Ciclo de vida](/motor-analise/ciclo-de-vida) para o detalhe de status e verdicts.

Blocos marcados como **ignorar** nos templates são opt-in: vêm desligados por padrão e passam a contar quando você muda a ação para alerta ou bloqueio em uma engine própria.

## Como o `engine_id` é resolvido

Ao criar uma análise, a API resolve a engine nesta ordem:

1. **`engine_id` explícito no body** — a engine precisa existir, pertencer ao seu workspace (ou ser um template do sistema) e ter o `subject_type` compatível com o documento (`pj` para CNPJ, `pf` para CPF).
2. **Engine padrão do workspace** — se `engine_id` for omitido e o workspace tiver uma engine padrão para aquele `subject_type`, ela é usada.
3. **Template do sistema** — sem engine padrão, a API usa o template global do Sherlocker para o `subject_type` (descritos abaixo).

Se nenhuma das três opções resolve, a resposta é `422` com code [`no_engine`](/problems/no_engine).

### Erros de resolução

| Situação | Resposta |
|----------|----------|
| `engine_id` não existe ou pertence a outro workspace | `404` [`not_found`](/problems/not_found) |
| `engine_id` arquivado | `422` [`no_engine`](/problems/no_engine) |
| `subject_type` da engine incompatível com o documento (ex.: engine `pj` para um CPF) | `422` [`no_engine`](/problems/no_engine) |
| Nenhuma engine resolvida (sem `engine_id`, sem padrão do workspace, sem template) | `422` [`no_engine`](/problems/no_engine) |

## Onde as engines são geridas

Engines são criadas, editadas, definidas como padrão e arquivadas **no app Sherlocker** (interface web). A API `/v1` não tem endpoints de CRUD de engines — hoje ela só consome uma engine já existente via `engine_id` ou pela resolução automática. Para criar uma política própria (mudar ações, ajustar parâmetros, ativar blocos opt-in), use o app.

## Templates do sistema

Quando o workspace não tem engine padrão e o `engine_id` é omitido, a análise roda com o template global do Sherlocker para o `subject_type`. São políticas conservadoras: irregularidade cadastral, óbito, sanção nacional, trabalho escravo e eventos de falência/recuperação judicial bloqueiam; sinais financeiros (Serasa, dívida ativa) e processos judiciais relevantes geram alerta.

Os parâmetros listados abaixo são os valores padrão do template. Cada bloco aceita parâmetros configuráveis por engine no app — o catálogo completo está em [Blocos](/motor-analise/blocos).
