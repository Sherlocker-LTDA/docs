Quando a operação chega a `completed`, o campo `titulos[]` do `GET /v1/operations/{id}` traz um item por título do borderô. Esta página é a referência desse shape, dos estados de `nfe_status` e da validação cruzada com os XMLs de NFe.

## Shape de um título

```json
{
  "seu_numero": "DUP-0001",
  "sacado_document": "12345678000190",
  "valor": 1234.56,
  "vencimento": "2026-08-01",
  "verdict": "aprovado",
  "nfe_status": "pass",
  "cedente_analysis_id": "a1b2c3d4-0000-0000-0000-000000000010",
  "sacado_analysis_id": "a1b2c3d4-0000-0000-0000-000000000011"
}
```

| Campo | Tipo | Descrição |
|-------|------|-----------|
| `seu_numero` | string | Identificador do título no arquivo remessa (campo "seu número" do CNAB 400) |
| `sacado_document` | string | Documento do sacado (apenas dígitos), extraído do CNAB |
| `valor` | number | Valor do título |
| `vencimento` | string | Data de vencimento (`YYYY-MM-DD`) |
| `verdict` | enum | `aprovado` \| `alerta` \| `reprovado` \| `incompleto` — veredito consolidado do título (veja [Ciclo de vida](/credito/ciclo-de-vida)) |
| `nfe_status` | enum | Resultado consolidado dos blocos de NFe do título — tabela abaixo |
| `cedente_analysis_id` | UUID \| null | Análise do cedente no Motor de Análise (a mesma para todos os títulos da operação); `null` se a análise da entidade não estiver disponível |
| `sacado_analysis_id` | UUID \| null | Análise do sacado no Motor de Análise (compartilhada entre títulos do mesmo sacado); `null` se a análise da entidade não estiver disponível |

`cedente_analysis_id` e `sacado_analysis_id` são análises **normais**: consulte `GET /v1/analyses/{id}` para o detalhamento completo (`verdict`, `blocks`, `coverage`) de cada entidade, no formato do [Motor de Análise](/motor-analise/ciclo-de-vida).

## Validação cruzada com NFe

O campo opcional `nfe_zip_base64` do `POST /v1/operations` recebe um **ZIP com os XMLs de NFe** dos títulos, em base64 (máximo de 32 MB decodificado). Quando enviado, o motor procura o XML correspondente a cada título e cruza os dados do CNAB com os da nota — a duplicata bate com uma NFe real?

<Note>
  O envio de XMLs é **opcional e sujeito à disponibilidade do recurso no beta**: se o recurso de XML estiver desabilitado no ambiente, o campo é aceito e ignorado, sem erro — a validação dos títulos segue apenas com os dados do CNAB.
</Note>

<CodeGroup>
```bash cURL
CNAB_B64=$(base64 -i remessa-0605.rem | tr -d '\n')
NFE_B64=$(base64 -i nfes-0605.zip | tr -d '\n')

curl -X POST "https://<API_HOST>/v1/operations" \
  -H "Authorization: Bearer slhk_sua_chave_aqui" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "{
    \"cnab_base64\": \"$CNAB_B64\",
    \"nfe_zip_base64\": \"$NFE_B64\",
    \"file_name\": \"remessa-0605.rem\"
  }"
```

```python Python
import base64
import uuid
import requests

def b64(path: str) -> str:
    with open(path, "rb") as f:
        return base64.b64encode(f.read()).decode()

resp = requests.post(
    "https://<API_HOST>/v1/operations",
    headers={
        "Authorization": "Bearer slhk_sua_chave_aqui",
        "Idempotency-Key": str(uuid.uuid4()),
    },
    json={
        "cnab_base64": b64("remessa-0605.rem"),
        "nfe_zip_base64": b64("nfes-0605.zip"),
        "file_name": "remessa-0605.rem",
    },
)
print(resp.status_code, resp.json())
```

```javascript Node.js
import { readFileSync } from "node:fs";

const b64 = (path) => readFileSync(path).toString("base64");

const resp = await fetch("https://<API_HOST>/v1/operations", {
  method: "POST",
  headers: {
    Authorization: "Bearer slhk_sua_chave_aqui",
    "Content-Type": "application/json",
    "Idempotency-Key": crypto.randomUUID(),
  },
  body: JSON.stringify({
    cnab_base64: b64("remessa-0605.rem"),
    nfe_zip_base64: b64("nfes-0605.zip"),
    file_name: "remessa-0605.rem",
  }),
});
console.log(resp.status, await resp.json());
```
</CodeGroup>

<Note>
  Durante o beta, substitua `<API_HOST>` pelo host fornecido pelo time Sherlocker. O host definitivo será publicado na promoção a produção.
</Note>

<Tip>
  O ZIP de NFe entra no hash canônico da idempotência (SHA-256 do conteúdo): reenviar o mesmo CNAB com um ZIP diferente e a mesma `Idempotency-Key` resulta em `409 idempotency_conflict`. Veja [Idempotência](/credito/idempotencia).
</Tip>

## Estados de `nfe_status`

O campo consolida os **blocos de NFe** do título. Dois estados indicam que a validação não rodou; os outros quatro refletem o **pior status** entre os blocos de NFe executados (a mesma escala de status de bloco do [Motor de Análise](/motor-analise/ciclo-de-vida)):

| `nfe_status` | Significado |
|--------------|-------------|
| `no_key` | O título não traz chave de NFe no CNAB — não há o que validar |
| `not_checked` | A engine da operação não tem nenhum bloco de NFe ativo — validação não executada |
| `pass` | Todos os blocos de NFe do título passaram sem ressalvas |
| `alert` | Pior status entre os blocos de NFe: ponto de atenção (ex.: divergência tolerada pela engine) |
| `blocked` | Pior status entre os blocos de NFe: impeditivo (ex.: divergência ou ausência de lastro tratada como bloqueio) |
| `unavailable` | Pior status entre os blocos de NFe: alguma verificação não pôde ser executada (fonte ou dado indisponível) |

Como cada bloco de NFe reage — o que vira `alert`, o que vira `blocked` — depende da configuração da [engine de borderô](/credito/engines), e o resultado dos blocos entra no `verdict` consolidado do título.

<Warning>
  `no_key` e `not_checked` não são problemas — são a **ausência de validação**. Se a sua esteira exige lastro de NFe para todos os títulos, envie sempre o `nfe_zip_base64`, use uma engine com blocos de NFe ativos e trate `alert`, `blocked` e `unavailable` na sua regra de aprovação.
</Warning>

## Limites dos arquivos

| Campo | Formato | Limite (decodificado) |
|-------|---------|-----------------------|
| `cnab_base64` | CNAB 400 remessa (`.rem`/`.txt`) em base64 | 16 MB |
| `nfe_zip_base64` | ZIP com XMLs de NFe em base64 | 32 MB |

Arquivos acima do limite, base64 inválido ou CNAB que não parseia retornam `400 validation_error` — e nada é cobrado, já que o débito só acontece após o parse. Veja [Erros](/motor-analise/erros).
