A área **Plataforma** reúne a documentação dos novos contratos de integração para capacidades que já existem — ou estão sendo preparadas — no ecossistema Sherlocker. Ela cobre o ciclo completo de uma investigação: iniciar um trabalho, acompanhar a execução, consultar resultados, receber eventos e exportar artefatos.

<Warning>
  A implementação destes contratos existe **somente no checkout local em
  revisão**. As migrations não foram aplicadas, os workers permanecem
  desabilitados por padrão e não há disponibilidade observada em produção. Uma
  funcionalidade existir no app Sherlocker não significa que sua API pública já
  esteja liberada. Use somente endpoints cuja página declare explicitamente que
  o acesso foi habilitado para o seu workspace.
</Warning>

## Endereço público e rota interna

O mesmo caminho aparece de duas formas porque existe uma camada pública na frente do backend:

| Contexto                          | Forma                                      | Para quem                                                          |
| --------------------------------- | ------------------------------------------ | ------------------------------------------------------------------ |
| API pública externa da Plataforma | `https://api.sherlocker.com.br/api/v1/...` | Clientes e integrações autorizadas quando o contrato for liberado  |
| Rota do backend                   | `/v1/...`                                  | Serviços internos, código dos controllers e operação da plataforma |

Para uma futura integração externa com estes contratos, a base normativa é `https://api.sherlocker.com.br/api/v1`. A presença de um controller interno em `/v1` **não publica automaticamente** esse endpoint na API externa: ainda são necessários contrato estável, autenticação por chave de API, autorização por workspace, documentação e liberação operacional.

<Note>
  As páginas desta área descrevem contratos antes da disponibilidade pública
  para orientar a implementação e permitir sua revisão. O status informado na
  página de cada produto prevalece sobre exemplos de URL ou payload.
</Note>

## Fundação comum dos contratos

As APIs da Plataforma convergem para os mesmos princípios:

- **Workspace como fronteira de autorização** — uma chave não acessa recursos de outro workspace.
- **Execuções duráveis para operações demoradas** — criação assíncrona, consulta de status e resultado terminal, sem depender de uma conexão aberta do cliente.
- **Idempotência nas escritas** — retries não devem gerar trabalho ou cobrança em duplicidade.
- **Cobrança e estorno rastreáveis** — quando aplicável, o consumo pertence ao workspace e falhas elegíveis são compensadas.
- **Polling como contrato autoritativo** — webhooks e realtime podem reduzir latência, mas não substituem a consulta do estado persistido.
- **Artefatos privados** — exports e arquivos são entregues por URLs temporárias, sem tornar o bucket público.

Esses princípios orientam a implementação local. Consulte a página do produto e o OpenAPI publicado antes de integrar.
