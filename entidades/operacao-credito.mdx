Uma **Operação** representa a análise de um borderô CNAB 400 no [Motor de Borderô](/credito/introducao). É criada via `POST /operations` (`multipart/form-data`), processada de forma assíncrona, consultada por polling em `GET /operations/{id}` e tem o resultado hierárquico em `GET /operations/{id}/result`.

## Ciclo de vida

```
queued → processing → completed | failed
```

Operações que terminam em `failed` têm os tokens reembolsados automaticamente. Detalhes em [Ciclo de vida](/motores/ciclo-de-vida).

## Envelope de status (`GET /operations/{id}`)

Todos os campos estão sempre presentes:

| Campo | Tipo | Descrição |
|-------|------|-----------|
| `id` | UUID | Identificador único da operação |
| `status` | enum | `queued`, `processing`, `completed`, `failed` |
| `file_name` | string | Nome do arquivo CNAB enviado |
| `file_size` | number \| null | Tamanho do arquivo em bytes (`null` em operações antigas) |
| `engine_id` | string | Engine de borderô efetivamente usada |
| `titulo_count` | number \| null | Total de títulos do borderô; `null` até `completed` |
| `approved_count` / `blocked_count` / `alert_count` | number \| null | Contagem de títulos por status; `null` até `completed`. A soma fecha com `titulo_count` — `alert_count` inclui os títulos com análise incompleta (fonte indisponível) |
| `created_at` / `queued_at` / `processing_at` / `completed_at` | datetime | Timestamps ISO 8601; `processing_at` é `null` enquanto `queued`, `completed_at` só é preenchido em `completed` |
| `error` | string \| null | Mensagem de erro; preenchida apenas em `failed` |

## Resultado (`GET /operations/{id}/result`)

Disponível apenas quando `completed` (antes disso, [`409 conflict`](/problems/conflict)). Devolve a árvore **cedente → sacados → títulos** — cada nó com `status` (`approved` | `blocked` | `alerted`, rollup worst-of) e `issues[]` (violações de regra) — junto com:

| Campo | Descrição |
|-------|-----------|
| `summary` | Contagens e valores do dataset completo: `total_titulos`, `approved`/`blocked`/`alerted`, `total_value`/`approved_value`/`blocked_value`/`alerted_value`, `sacados.total`/`sacados.with_issues`, `cedente.status`. Não muda com `?filter` |
| `coverage[]` | Por provider consultado: `requested`, `succeeded`, `failed_keys` |
| `degraded_rules[]` | Regras não avaliadas por fonte indisponível: `rule_id`, `provider`, `titulos_affected` |
| `engine_id` / `engine_name` / `timestamp` | Engine usada e momento do resultado |

Por padrão (`?filter=issues`), títulos aprovados e sacados sem problemas são podados; `?filter=all` devolve a árvore completa. Cada título traz `numero`, `valor`, `data_vencimento`, `nfe_chave` e as suas issues — o shape completo está em [Títulos e NFe](/credito/titulos-e-nfe).
