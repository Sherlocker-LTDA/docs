Uma **Operação** representa a análise de um borderô CNAB 400 no [Motor de Borderô](/credito/introducao). É criada via `POST /v1/operations` (`multipart/form-data`), processada de forma assíncrona, consultada por polling em `GET /v1/operations/{id}` e tem o resultado hierárquico em `GET /v1/operations/{id}/result`.

## Ciclo de vida

```
queued → processing → completed | failed
```

Operações que terminam em `failed` têm os tokens reembolsados automaticamente. Detalhes em [Ciclo de vida](/motores/ciclo-de-vida).

## Envelope de status (`GET /v1/operations/{id}`)

Todos os campos estão sempre presentes:

| Campo | Tipo | Descrição |
|-------|------|-----------|
| `id` | UUID | Identificador único da operação |
| `status` | enum | `queued`, `processing`, `completed`, `failed` |
| `fileName` | string | Nome do arquivo CNAB enviado |
| `fileSize` | number \| null | Tamanho do arquivo em bytes (`null` em operações antigas) |
| `engineId` | string | Engine de borderô efetivamente usada |
| `tituloCount` | number \| null | Total de títulos do borderô; `null` até `completed` |
| `approvedCount` / `blockedCount` / `alertCount` | number \| null | Contagem de títulos por status; `null` até `completed`. A soma fecha com `tituloCount` — `alertCount` inclui os títulos com análise incompleta (fonte indisponível) |
| `createdAt` / `queuedAt` / `processingAt` / `completedAt` | datetime | Timestamps ISO 8601; `processingAt` é `null` enquanto `queued`, `completedAt` só é preenchido em `completed` |
| `error` | string \| null | Mensagem de erro; preenchida apenas em `failed` |

## Resultado (`GET /v1/operations/{id}/result`)

Disponível apenas quando `completed` (antes disso, [`409 conflict`](/problems/conflict)). Devolve a árvore **cedente → sacados → títulos** — cada nó com `status` (`approved` | `blocked` | `alerted`, rollup worst-of) e `issues[]` (violações de regra) — junto com:

| Campo | Descrição |
|-------|-----------|
| `summary` | Contagens e valores do dataset completo: `totalTitulos`, `approved`/`blocked`/`alerted`, `totalValue`/`approvedValue`/`blockedValue`/`alertedValue`, `sacados.total`/`sacados.withIssues`, `cedente.status`. Não muda com `?filter` |
| `coverage[]` | Por provider consultado: `requested`, `succeeded`, `failedKeys` |
| `degradedRules[]` | Regras não avaliadas por fonte indisponível: `ruleId`, `provider`, `titulosAffected` |
| `engineId` / `engineName` / `timestamp` | Engine usada e momento do resultado |

Por padrão (`?filter=issues`), títulos aprovados e sacados sem problemas são podados; `?filter=all` devolve a árvore completa. Cada título traz `numero`, `valor`, `dataVencimento`, `nfeChave` e as suas issues — o shape completo está em [Títulos e NFe](/credito/titulos-e-nfe).
